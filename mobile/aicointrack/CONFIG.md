# Mobile App Configuration Guide

## Configuration Files

### `lib/config/constants.dart`

This file contains all hardcoded configuration constants for the mobile app. Update this file based on your deployment environment:

```dart
class AppConstants {
  // Backend API Configuration
  // Update this based on your environment:
  // - Local: http://localhost:8000
  // - Remote Dev: https://your-devtunnel.uks1.devtunnels.ms
  // - Staging: https://staging-api.example.com
  // - Production: https://api.example.com
  static const String BACKEND_URL = 'https://your-backend-url';
  
  static const int HTTP_TIMEOUT = 30;  // seconds
}
```

### Firebase Configuration

Firebase is configured via two files (already set up by FlutterFire CLI):

1. **`lib/firebase_options.dart`** - Firebase project credentials
   - Contains: Project ID, API Key, App ID, etc.
   - Generated by FlutterFire CLI
   - Safe to commit to git (not sensitive)

2. **`pubspec.yaml`** - Firebase dependencies
   - Firebase Core, Auth, etc.
   - Already configured

## Environment-Specific Setup

### Local Development
- Backend URL: `http://localhost:8000` (if testing locally)
- Or use dev tunnel URL: `https://your-devtunnel.uks1.devtunnels.ms`

### Production
- Backend URL: `https://api.example.com` (your production domain)
- Use environment-specific Firebase project if available

## Building for Different Environments

### Update for Development
```bash
# Edit lib/config/constants.dart
BACKEND_URL = 'https://zvhdw4k2-8000.uks1.devtunnels.ms'

flutter run
```

### Update for Production
```bash
# Edit lib/config/constants.dart
BACKEND_URL = 'https://your-production-api.com'

# Build APK/IPA
flutter build apk --release
flutter build ios --release
```

## No .env File Needed

Unlike the backend, Flutter apps don't use .env files. Instead, all configuration is in Dart:

- ✅ `lib/config/constants.dart` - App constants (ok to commit)
- ✅ `lib/firebase_options.dart` - Firebase config (ok to commit)
- ❌ Secrets should NEVER be in app (use backend to store/verify)

## Security Best Practices

1. **Never hardcode API keys** in the app
   - Only store public Firebase keys that are in firebase_options.dart

2. **Never hardcode secrets** in the app
   - All sensitive operations go through the backend

3. **Keep sensitive data on the backend**
   - Database passwords, API keys, etc. → backend .env only

4. **Use Firebase Auth** for user authentication
   - Token is verified by backend, not client
